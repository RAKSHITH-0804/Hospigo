## Top 10 problems, ordered by risk

1. **Part payment, pending balance (UC-16) and the Emergency flag are NOT built, though the plan requires them.** The API refuses any payment that is not exactly the bill total (`apps/api/src/modules/opd-visits/billing-helpers.ts:62-65`, checked by me); the database queue gate refuses to queue a part-paid visit; no code mentions emergency at all (grep returned nothing, checked by me). What exists is split payment across modes with one receipt. Decision D6 (part-paid and Emergency visits in the doctor queue) is therefore half built, and `docs/handoff-phase2.md` wrongly lists these as Step 4a work.
2. **Nobody except the dev seed can set up a hospital: the masters and settings have no write route or screen.** Prices, doctor fees, tests, medicines, payment modes, vitals fields, number series, doctor availability, timings and leave, branches and access codes are written only by `prisma/seeds/dev-tenants.ts` (reviewers A1 to A3; number-series writer re-checked by me). A new hospital gets `409 NUMBER_SERIES_NOT_CONFIGURED` on its first visit; non-main branches carry `dev-placeholder-<id>` access codes; Excel upload (8b) and the import state machine have no controller. Without these, release 1 cannot be handed to a real hospital.
3. **Mock data is still served on real routes.** `/admin` (hospital list) and `/book/[code]` import `apps/web/src/mock/*` ("Demo Hospital One..Four", mock doctors and slots, fake brand colours; `components/admin/hospitals-screen.tsx`, `components/book/booking-screen.tsx`). This breaks the standing rule "no fake numbers, mock tiles or placeholder data on real screens" (a sample-data badge is shown, but the rule has no such exception).
4. **UI text rule is not enforced everywhere.** Sentence-like text is typed directly in `app/login/page.tsx`, `forgot-password`, `reset-password`, `activate`, `change-password`, `components/admin/hospitals-screen.tsx`, `components/book/booking-screen.tsx`, `storage-status-card.tsx`. The scan test `config/staff-ui-copy-scan.spec.ts` only scans `components/ui`, `components/shell`, `components/patients`, `app/app/patients`, `app/app/settings`; the claim "scan tests enforce zero hardcoding" is therefore only partly true. My heuristic found no such text in the OPD, staff, account, image, print and doctor screens.
5. **An unapproved rule changes prices: "repeat visit within N hours is free".** Not in `use-cases-opd.md` or `schema-opd.md`; recorded only in `docs/decisions/decisions-4a.md` (section "Free repeat-visit window") with no named approver. It makes the consultation fee 0 even when the receptionist picks "New", and the dev seed turns it on at 24 hours. It needs Rakshith's explicit approval or removal.
6. **Registration fee can never be charged again after a cancelled first visit.** Schema-opd open item 2 (default "Yes") says it should be; `patient_registration_fees.voided_at` exists but the app role has no UPDATE right, so nothing can void it (reviewer A3; only noted as a follow-up in decisions-6a). Also: tax switched on makes billing fail with `501`, vitals ranges only warn (UC-07 asks for validation), a cancelled visit keeps its token number with no void marker.
7. **Behaviour that differs from the written decisions.** Doctor leave days BLOCK assignment (`opd-masters/doctor-availability.service.ts:104-106`, checked by me; test `opd-masters.spec.ts:708-722`) while D6 says only timings warn. SuperAdmin reads queue, vitals and notes (`prisma/seeds/reference.ts:93-102`; test `opd-visits.endpoints.spec.ts:2022`) although decisions-4a Q6 says notes are for Doctor and Nurse only (decisions-7 later approved "SuperAdmin sees everything", the 4a text was never updated). The raise-UHID endpoint is open to Branch Admin while its code comment says SuperAdmin only.
8. **Dependency risk: `npm audit` shows 36 vulnerabilities, 5 high.** High: `multer` (DoS via a pending async fileFilter, GHSA-q7qp-rjg7-q26m, range 2.0.0 to 2.4.0, installed 2.4.0 under `@nestjs/platform-express@11.2.8`, so it is the library behind the 7e upload; the code does not set a `fileFilter`, so the stated trigger is not used here, UNVERIFIED beyond that), `effect` and `prisma`/`@prisma/config` (ReDoS, build-time tooling), `@nestjs/platform-express` (via multer). 31 moderate (jest, typescript-eslint, glob, minimatch, js-yaml, uuid, exceljs, @nestjs/swagger and cli). Nothing was fixed; the `audit` CI job is red by design.
9. **Some "never changes" rules rest on missing grants, not triggers.** `stored_images` and `uhid_counters` have no delete or truncate trigger; only the absence of a DELETE grant for `hospigo_app` stops a delete, and the owner role (also BYPASSRLS) can delete or disable triggers (reviewer A3, SQL above). `prescription_items` gives the app role DELETE, limited by a trigger to draft notes. This is acceptable only if owner credentials never run on the application server (go-live item).
10. **Smaller correctness and hygiene items.** UC-02 duplicate warning ignores date of birth (`patients.service.ts:248-265` matches phone and name); `enableImplicitConversion: true` at `patients/patient-validation` line 130 can turn the text "false" into true for `confirmDuplicate` (reported by a reviewer, line exists, behaviour not tested by me); relative name and relation are not printed on the slip; token is not mandatory on a custom receipt template; tracker has stale rows ("Prescription print: Open", "7c: Planned"); the Step 3c Postman collections named in `docs/guides/dev-commands.md` are not in `postman/collections`; collections 7, 7b, 7c and 7e have never been run.
