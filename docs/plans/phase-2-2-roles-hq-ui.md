## 1. Why (the manager's words, short)

1. The site must look like a real hospital system: **no "Demo", "Mock", "Test" hospital or user names anywhere**. Only two hospitals stay: **Nandavana Multispeciality Hospital** and **Sagarika Heart and Eye Centre**. Demo North (Mandara Family Hospital) and Demo South (Taranga Health Centre) are removed with ALL their data.
2. **HQ (Indigo, the software owners) must never enter a hospital** (DPDP Act, privacy). HQ onboards and configures hospitals and monitors them with counts only.
3. "Tenant Admin" is the same thing as **Super Admin** (the hospital owner). There is no separate Tenant Admin role.
4. The UI is not good enough for a demo or live use. Redesign the pages using `docs/design/hospigo_hospital_operations_platform.html` as the reference. **Keep the current left sidebar colours, the login page colours and the blue buttons and links.** Only the pages change.

## 2. Roles (final)

| Role                        | Who                         | Rules                                                                                                                                                                                                                                                    |
| --------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **HQ Admin**                | Indigo, the software owners | Creates hospitals and configures them (modules, branches, print designs and logo, terminology, first Super Admin, one-time password reset), monitors them, creates HQ Staff and ticks what each may do and which hospitals. **No Enter hospital, ever.** |
| **HQ Staff**                | Indigo employees            | Only the permissions HQ Admin ticked (simple tick-boxes per person, not named roles), only for the hospitals HQ Admin ticked. **Never enters a hospital.**                                                                                               |
| **Super Admin**             | Hospital owner              | HQ creates the FIRST one; afterwards the Super Admin creates other Super Admins and Admins. Hospital-wide. Gives each Admin the branches he may operate.                                                                                                 |
| **Admin**                   | Branch admin                | Hospital-wide only inside ONE hospital (one owner). Example: Hospital A has 5 branches; Admin1 gets branches 1 and 2, Admin2 gets 3, 4 and 5; nobody works for Hospital B. The Super Admin assigns the branches.                                         |
| Receptionist, Nurse, Doctor | Staff                       | As now.                                                                                                                                                                                                                                                  |

Names on screen: **HQ Admin, HQ Staff, Super Admin, Admin** (never "Indigo Owner", "Indigo Employee", "Tenant Admin"). Rename the HQ demo accounts to `hq.admin@indigo.example.org` and `hq.staff@indigo.example.org` (password variable stays `SEED_INDIGO_PASSWORD`; the showcase seed falls back to `SEED_STAFF_PASSWORD`).

**Admin views.** An Admin with several branches has the branch switcher (one active branch) AND an "All my branches" option on the read and review screens only: Dashboard, Reports, OPD queue, Refund requests (with a branch column or filter). Changes (taking cash, starting a visit, prices) always need one active branch; approving a refund works on any request of an assigned branch. Super Admin gets the same option for all branches.

**Monitoring (HQ), counts only.** Per hospital: visits today / last 7 days / last 30 days, active users (signed in in the last 30 days), last activity (time of last visit or sign-in). HQ home: one system health status (API, database, storage, migrations). **No patient names, no money.** Implement with SECURITY DEFINER aggregate functions callable by `hospigo_hq` only (the HQ login must still not read any clinical table).
