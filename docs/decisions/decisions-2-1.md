# Decisions: Phase 2.1 (demo changes)

Source: `docs/plans/phase-2-1-demo-changes.md`, written by Rakshith (with Claude) on 26 Nov 2026 after the manager demo of Phase 2 (OPD). The next meeting is with hospitals, so the product must look real and the workflow must match how hospitals like Sukshema work. Phase 2.1 is built in four steps, each its own branch, PR and report: 2.1a, 2.1b, 2.1c, 2.1d. This file is updated as each step finishes.

Phase 2 (Steps 1 to 9) is merged into `develop` (Step 9: PR #62, merge commit `ef46910`).

## 1. Decisions (Rakshith, 26 Nov 2026)

| #   | Decision                                                                                                                                                                                                                                                                                                                                |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

#### Security gate for 2.1b (self-review as an attacker)

| What was tried                                                                                                                | Result                                                                                                                                            | Covered by                              |
| ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| Forged or wrong token on the Indigo entry (hospital token, missing token, nonsense)                                           | refused (401); there is no "Indigo" claim to forge                                                                                                | `indigo-access.endpoints.spec.ts`       |
| An Indigo person switched off, then entering or refreshing                                                                    | entry 403; refresh 401 and the session family is revoked; old refresh token stays dead                                                            | same                                    |
| An Employee reaching an unassigned or unknown hospital                                                                        | 403 with the very same body (no enumeration); removing the assignment ends the session at the next refresh                                        | same                                    |
| An Employee reaching patient data                                                                                             | no patient, visit, notes, billing, report, template or Indigo-log permission; `/patients` is 403 from the API                                     | same                                    |
| An Owner turned into an Employee                                                                                              | the Owner role is replaced at the next entry (one live assignment)                                                                                | same                                    |
| Hospital users touching the hidden Indigo user (list, count, open, rename, switch off, give it roles; log in with a password) | not listed, 404, role refused, login 401                                                                                                          | same                                    |
| Creating or changing the Indigo flag from SQL                                                                                 | refused by the trigger (the flag only comes from the entry code)                                                                                  | same                                    |
| Reading the Indigo log of another hospital, or without the permission                                                         | only that hospital's SuperAdmin; other hospital sees nothing; 403 without the permission                                                          | same                                    |
| Editing or deleting the access log, the versions or the view log (also as the database owner login)                           | refused (append-only triggers, truncate refused)                                                                                                  | same, `opd-clinical.endpoints.spec.ts`  |
| A doctor editing, amending or adding an addendum after Complete                                                               | 409 / 403 / 409 retired                                                                                                                           | `opd-clinical.endpoints.spec.ts`        |
| An amend in another branch or another hospital; by nurse, receptionist, nobody                                                | 404 / 403                                                                                                                                         | same                                    |
| An amend with no reason, a 2-letter reason, no change, an emptied note, extra fields                                          | 400 or 409, nothing stored                                                                                                                        | same                                    |
| A doctor reading another patient without a log row; reading twice; another hour                                               | logged once per hour, never for the assigned doctor with an open visit; a nurse, receptionist or Admin cannot read it (403); another hospital 404 | same                                    |
| An Admin of two branches reaching a third branch through the switcher                                                         | not listed, not allowed; switching one assignment off removes the switcher at once                                                                | `branch-switch-admin.endpoints.spec.ts` |
| New tables and tenant isolation                                                                                               | RLS forced on the three new tenant tables and in the isolation and HQ-privilege tests; `hq_user_hospitals` is HQ-only                             | `rls.*.spec.ts`                         |
